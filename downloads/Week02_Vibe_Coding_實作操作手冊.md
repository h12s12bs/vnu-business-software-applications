## 二、實作關卡一：調度 AI 自動建立企業四層樹與 README 首頁

### 【步驟指引】
- **步驟 1**：登入 `github.com`，進入上週建立之倉儲 `vnu-business-docs`（若未建立，點擊右上角 `+` ➔ `New repository`，命名為 `vnu-business-docs`，勾選 `Add a README file`）。
- **步驟 2**：在倉儲首頁直接按鍵盤上的 **`.`（句點鍵）**，1 秒進入免安裝線上 VS Code！
- **步驟 3**：複製右側【任務一提示詞】，貼給 Antigravity 或 Gemini 網頁版。
- **步驟 4**：將 AI 產出的 Markdown 內容複製，貼入 VS Code 的 `README.md`，點擊左側原始碼管制提交或點擊右上角 Commit！

### 【提示詞（Prompt 寫在旁邊，點擊複製）】
```text
【角色設定】：你是一位頂級企業數位資產架構師與知識管理總監。
【背景情境】：我們是萬能科大企業管理系「商業軟體應用」專案團隊，正在 GitHub 建立標準化企業數位倉儲（Repository 名稱：vnu-business-docs）。
【約束限制】：
1. 建立標準四層樹狀資料夾治理架構，目錄代碼為：
   - 00_Admin（專案章程、權限名冊、行政規章）
   - 01_Raw_Data（未經加工的外部原始資料、市場調研報表）
   - 02_Working_Drafts（進行中的企劃草案、Word 底稿、數據分析過程）
   - 03_Deliverables（經總監簽核的最終交付報告、發布檔）
2. 產出一份專業的 README.md 導航首頁，包含專案簡介、四層目錄結構說明、ISO 8601 命名規範與團隊維護清單。
3. 語法必須完全符合 GitHub Markdown 規範。
【核心任務】：請為我起草產出完整的 README.md 原始內容，供我直接貼入 GitHub 專案首頁！
```

## 三、實作關卡二：指令 AI 自動生成標準公文與四欄對齊決策表格

### 【步驟指引】
- **步驟 1**：複製右側【任務二提示詞】。
- **步驟 2**：貼入 AI 對話視窗送出，觀測 AI 3 秒內自動計算冒號位置、繪製精準靠右對齊表格與引用框。
- **步驟 3**：在線上 VS Code 按快捷鍵 `Ctrl + Shift + V`（或點擊右上角放大鏡預覽圖示），親眼見證純文字自動變成排版美觀的商務公文！

### 【提示詞（Prompt 寫在旁邊，點擊複製）】
```text
【角色設定】：你是一位擁有 10 年跨國零售與商務管理經驗的總經理特助。
【背景情境】：公司正在推動「全台門市智慧數位轉型與 POS 系統升級專案」，需向董事會呈報標準公文與營運效益分析。
【約束限制】：
1. 產出標準 Markdown 商業公文：包含一級標題、二級案由、高階主管核示引用框 (>)。
2. 繪製一張四欄營運數據分析表（分區、門市數、鮮食報廢率改善、預估月效益/預算），數值與金額欄位強制靠右對齊 (|---:|)。
3. 條列 3 項具體行動對策，使用帶有負責人與截止日期的 Markdown 核選清單 (- [ ])。
4. 格式嚴謹工整，杜絕口語冗詞。
【核心任務】：請產出符合上述規格的完整 Markdown 公文草案！
```

## 四、實作關卡三：真實會議逐字稿 ✕ AI 自主結構化淬鍊

### 【步驟指引】
- **步驟 1**：複製下方【真實會議錄音逐字稿】與【任務三 Master 提示詞】。
- **步驟 2**：貼給 AI 代理人，觀測 AI 自主 ReAct 運算：自動過濾口語廢話 ➔ 自動計算 18 家門市 × 85,000 = 153 萬元 ➔ 自動繪製四欄對齊表格 ➔ 自動條列分工明確的待辦清單！
- **步驟 3**：取得完整 Markdown 會議決議底稿！

### 【原始會議逐字稿素材】
```text
【會議時間】：2026年9月21日 晚間例會
【出席人員】：總經理 David、營運部經理 Susan、資訊部經理 Kevin、財務部經理 Linda
【會議原始錄音速記】：
David（總經理）：「大家晚安。今天主要討論我們全台18家門市導入智慧零售POS系統的事情。Susan，你們營運部上個月鮮食報廢率到底降下來沒有？」
Susan（營運部）：「報告總經理，目前我們北區6家門市試辦電子標籤和即期品動態折扣，報廢率從上季的 8.2% 降到了 5.1%，光是鮮食一個月就省下 42 萬台幣！但是中區和南區門市還在用手動貼貼紙，報廢率還是高達 7.9%。」
David：「好，那這件事不能拖。Susan，妳在10月15號前，把中南區12家門市的電子標籤導入計畫和教育訓練時程排出來。Kevin，系統連線問題解決了嗎？」
Kevin（資訊部）：「資訊部這邊報告，新版雲端 POS 和庫存系統已經完成壓力測試。但是硬體採購需要追加預算，18家門市升級掃描槍和雙螢幕主機，每家門市報價是 85,000 元，總共需要 153 萬元。另外還有雲端伺服器每個月租金 35,000 元。」
Linda（財務部）：「我打個岔，財務部已經審核過這筆預算。153萬硬體採購可以動用第三季資本支出，但伺服器月租必須控制在年度 IT 運營預算內。另外，供應商合約必須加入 SLA 99.9% 正常運作保證，否則延遲上線每天要罰款千分之二。」
David：「很好，大家聽清楚。第一，資訊部 Kevin 在本週五（9/25）前把採購合約修改好送法務和 Linda 審核。第二，營運部 Susan 負責門市店長培訓。第三，全案目標在11月1日全台18家門市正式上線。請大家按照 ISO 規範，把這份會議記錄整理成正式 Markdown 專案企劃底稿，存入雲端儲存庫。」
```

### 【任務三 Master CLEAR 提示詞（Prompt 寫在旁邊，點擊複製）】
```text

【背景情境】：公司剛召開完第 4 季門市智慧零售升級專案例會，現場口語對話零碎雜亂。
【約束限制】：
1. 嚴格使用繁體中文（台灣商務專業語氣），格式工整清爽。
2. 絕不捏造未提及的數據；涉及金額與時程必須 100% 精準計算。
3. 輸出需包含：
   (a) 正式會議基本資訊與案由
   (b) 門市營運分析四欄表格（分區、門市數、報廢率改善、採購預算/效益，金額欄位強制靠右對齊 |---:|）
   (c) 具備負責人與明確截止日期的 Markdown 待辦核選清單 (- [ ])。
【核心任務】：請將提供的會議錄音逐字稿整理為符合 ISO 規範之正式 Markdown 會議決議底稿！
```

## 五、實作關卡四：專案總監 HITL 審核 ✕ 指令 AI 自主修復 ✕ GitHub 雲端交付

### 【步驟指引】
- **步驟 1**：學生扮演專案總監核對數據：18 家門市每家 85,000 元，總計是否準確等於 153 萬元？SLA 99.9% 條款是否齊全？
- **步驟 2**：發現小瑕疵，**【絕不手動修改任何一行字】**！複製下方【自我修復提示詞】貼給 AI，AI 瞬間自動調整表格置中、補上 SLA 與優先級標籤！
- **步驟 3**：可直接指令 Antigravity 桌面版自動建檔並 push 到 GitHub；若使用網頁版，則在 GitHub 線上新建檔案 `03_Deliverables/2026-09-21_門市數位轉型會議記錄_v1.0.md` 貼入成果點擊 Commit！下課手機打開隨時展示！

### 【自我修復提示詞（Prompt 寫在旁邊，點擊複製）】
```text
【角色設定】：你是一位資深專案總監與敏捷教練。
【背景情境】：剛才由你協助起草的「門市數位轉型會議記錄」初稿已完成，現在進行專案總監複審 (Human-in-the-Loop)。
【修復需求】：
1. 營運表格中，請將第二欄「門市數」由原本靠左改為「置中對齊 (|:---:|)」。
2. 在財務部 Linda 的決議後面，強調「供應商若延遲上線，每日處以合約總額千分之二罰款之 SLA 條款」。

4. 在文末追加一節「期末延伸效益」，說明本專案將於第 11-12 週導入 Excel 儀表板、第 15 週串聯 PPT 簡報。
【交付指令】：
請依上述修改輸出完整內容，直接幫我存入本專案的「03_Deliverables/2026-09-21_門市數位轉型會議記錄_v1.0.md」，並自動執行 git add, git commit 與 git push 推送到 GitHub 雲端！
```
